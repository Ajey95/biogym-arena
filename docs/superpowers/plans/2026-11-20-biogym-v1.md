# BioGym Arena V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver an executable BioGym Arena vertical slice with three scientific rooms, versioned episodes, a trainable policy, TransferArena, evaluation, pixel laboratory, and run export.

**Architecture:** Python FastAPI owns the episode state machine, independent verification, events, training, evaluation, and ZIP. React/Vite renders a 2D pixel laboratory and reads the API. The first local cases use explicit FIXTURE data; live scientific adapters report LIVE only after a successful upstream call.

**Tech Stack:** Python 3.12, FastAPI, Pydantic, PyTorch, SQLite for local durable storage, React 19, TypeScript, Vite, browser Canvas/CSS for interactive pixel world plus project art assets.

**Spec:** docs/PRD.md and docs/design/top-down-flow/README.md.

## Global Constraints

- No scientific or training result may be fabricated.
- LIVE, CACHED, FIXTURE, and SYNTHETIC are distinct source statuses.
- A trained-policy claim needs optimizer steps, changed policy hash, and separate held-out evaluation.
- LabOps and ResearchSense remain separate score dimensions.
- Required episode attempts unlock doors whether successful or failed.
- The full run ZIP must support offline event replay; fresh computational rerun has separately disclosed dependencies.

## Review Focus

- Malformed or unauthorized actions return a recorded failure without executing a tool.
- Duplicate action IDs do not duplicate execution or rewards.
- A failed episode still unlocks its room once recorded.
- An attempted provenance mislabel cannot pass ResearchSense.
- Baseline and updated policy use the same held-out case, source status, budget, and grader.

## File map

- backend/biogym/models.py: typed case, action, event, result contracts.
- backend/biogym/cases.py: reviewed starter case manifests and split assignments.
- backend/biogym/tools.py: scientific tool gateway with fixture and live adapters.
- backend/biogym/engine.py: reset/step/state, budgets, independent grading.
- backend/biogym/store.py: durable attempts, events, policies, evaluations.
- backend/biogym/policy.py: trainable PyTorch policy, checkpoint and update proof.
- backend/biogym/evaluation.py: frozen matched comparison and metrics.
- backend/biogym/export.py: validated full run ZIP.
- backend/biogym/api.py: HTTP endpoints.
- frontend/src: game map, room, replay, evaluation and export UI.
- backend/tests: contract, engine, training, evaluation and export tests.
